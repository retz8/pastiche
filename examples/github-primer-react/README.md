# Pastiche × Primer: a GitHub clone

This is a working GitHub clone, built on [Primer](https://primer.style),
GitHub's own design system. Every screen was produced by **[pastiche](https://github.com/retz8/pastiche)**
from a plain-language description of what the page should do. No screen was designed pixel-by-pixel,
and no generated code was hand-edited afterward.


## What you're looking at

This app adopts **`@primer/react`** as its component library and takes its design posture from
**primer.style**, GitHub's published design philosophy: functional, restrained, engineer-facing;
one primary action per surface; reach for an existing component before writing custom CSS.

Pastiche read that system once and wrote down everything that exists in it:

> **`149` components · `1113` tokens** catalogued from Primer.

That catalog is the entire reference the tool worked from, plus two short, hand-written guides
describing *how* the system is meant to be used (see [The guides that drove it](#the-guides-that-drove-it)).
No mockups, no Figma, no per-page art direction.


## The pages

Each page below was generated by handing Pastiche a single plain-language task, the kind of brief
a product manager or designer might write in a ticket. The exact wording is reproduced under
**Task prompt** on each page; the screenshot is what came out.

The prompts describe **intent** ("labels as colored tags",
"a danger zone that's visually distinct", "open and closed issues should be visually
distinguishable"), never specific components, colors, or measurements. Pastiche makes those
choices, and makes them the way the design system intends.

Full prompt set: [`pastiche-task-prompts.md`](docs/pastiche-task-prompts.md).

> **A note on honesty.** None of the *generated code* was edited by hand. But the two docs that
> pastiche reads (`KNOWLEDGE.md` and `WISDOM.md`) were refined across several runs as gaps surfaced.
> That's how pastiche is meant to be used, and how it gets sharper over time. The screenshots here
> are the output once those docs had settled.

## The guides that drove it

Pastiche didn't invent any of this from imagination. Everything above traces back to three
documents: one written by a machine, two written by a person.

| Document | What it is | In this example |
|---|---|---|
| `FACT.md` | The catalog of what exists in the design system, read straight from the code. Never hand-written. | `149` components · `1113` tokens |
| `KNOWLEDGE.md` | The designer's judgment, written down: *in this situation, use these components.* Curated by hand. | `51` scenarios across 12 sections |
| `WISDOM.md` | The rules that can't be read off the code, like *"only one primary button per area," "never use a raw color."* Curated by hand. | `20` rules |

If you're a designer, these last two are the interesting part. They're where your judgment lives.
A few of the actual entries that shaped the pages above:

**From `KNOWLEDGE.md`, situation → component:**
```markdown
Primary call-to-action on a page — the single most important action the user should take.
→ `Button` variant="primary"

Destructive action that requires confirmation before proceeding (e.g., delete, close permanently).
→ `Button` variant="danger"
→ `ConfirmationDialog` confirmButtonType="danger"

Empty state placeholder when a list or page has no content yet — guiding the user toward a first action.
→ `Blankslate`
→ `Blankslate.Visual`
→ `Blankslate.Heading`
→ `Blankslate.PrimaryAction`
```

**From `WISDOM.md`, always-true rules:**
```markdown
- [GENERAL] Never use raw hex, rgb, or px values; always reference Primer design tokens (`--fgColor-*`, `--bgColor-*`, `--borderColor-*`, `--shadow-*`).
- [Button] Never render more than one variant="primary" Button in a single button group or page region. Primary is the single highest-priority action.
- [FormControl] Never disable or hide the submit button, even when the form is invalid. Disabled buttons break keyboard navigation and leave users without feedback on what went wrong.
```

And `config.yaml` points pastiche at this app's library and tokens. `FACT.md` is generated from it:
```yaml
platform: claude-code

packages:
  - name: "@primer/react"
    types:
      - "node_modules/@primer/react/dist/index.d.ts"
      - "node_modules/@primer/react/dist/experimental/index.d.ts"

tokens:
  - node_modules/@primer/primitives/dist/css/functional/size/size.css
  - node_modules/@primer/primitives/dist/css/functional/spacing/space.css
  - node_modules/@primer/primitives/dist/css/functional/typography/typography.css
  # ...and the rest of Primer's functional token CSS
```

See the full set under [`pastiche/`](pastiche/).


## Reproduce it

```bash
cd examples/github-primer-react
npm install
npm run dev
```

The app's pastiche config (the `pastiche/` folder with FACT/KNOWLEDGE/WISDOM) is already committed.
To regenerate any page from scratch, launch Claude Code from this app's root with the bundled
pastiche plugin loaded:

```bash
claude --plugin-dir ../../dist/claude-code
```

Then, inside the session, run `/pastiche` with any task prompt from above:

```
/pastiche <paste any task prompt from above>
```

> **Note.** The pastiche plugin ships in this repo at `dist/claude-code`, so no separate
> install is needed. See the [main repository](https://github.com/retz8/pastiche) for details.
